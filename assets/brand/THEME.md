# VISHWAS.EXE / Unified Visual System

**Owner:** Vishwas Aithal  
**Scope:** Public GitHub profile, eight public repository README files and nine interactive GitHub Pages screens.  
**Identity:** Vishwas Aithal. Technical repository slugs and historic code identifiers remain unchanged.

## The look

The visual language is one nostalgic desktop with multiple programs. Every public repository gets a matching original SVG window with a shared layout, titlebar, taskbar and console. The title, short technical description and decorative animation are unique to the project. The shared interactive shell gives each GitHub Pages screen a consistent route bar, browser color, favicon and window chrome.

## Where the theme lives

- `assets/brand/vishwas-exe-main.svg`: personal profile banner.
- `assets/brand/vishwas-exe-*.svg`: eight project-specific README banners.
- `assets/brand/retro-shell.css`: shared navigation and retro window CSS.
- `assets/brand/favicon.svg`: original floppy-inspired V icon.
- `index.html`: ten-destination boot manager.
- `memory/index.html`: original windowed desktop.
- `museum/index.html`: 102-file searchable memory museum.
- `arcade/index.html`: original arcade, including pinball and Snake.
- `overload/index.html` and other `overload/` pages: games, tracker, network map, floppy capsule and retro utilities.
- `overload/qa.mjs`: static quality gate.
- `.github/workflows/overload-smoke.yml`: read-only CI workflow for static quality.

All repository README banners load images from **this public repository** using their exact shared source URLs. This makes the theme consistent while preserving each repository's technical details and individual media collection.

## Maintaining the universe

1. Keep the core palette, border treatment, window bars and global navigation shared.
2. Make the project's own panel, technical description and illustration distinct.
3. Do not remove the README's installation, setup, testing, security or contribution sections.
4. Keep previous artwork available inside expandable details, rather than deleting it.
5. Keep all private repository names, files and operational secrets out of public content.
6. Use factual GitHub metadata. Do not invent live uptime, stars, achievements or test results.
7. Keep third-party software, entertainment and game names as descriptive nostalgia only. Do not bundle copyrighted songs, artwork or commercial software.
8. Avoid long dash punctuation in visible GitHub text. Internal code syntax and functional identifiers should not be rewritten simply for visual branding.
9. Preserve reduced-motion alternatives, keyboard access and user-triggered sound.
10. Run `node overload/qa.mjs` before pushing changes to the public GitHub Pages source.

## GitHub limitations

The GitHub profile README itself renders Markdown, supported HTML and static or animated images. It cannot run a complete browser operating system inside the README. Interactive applications live on GitHub Pages and are linked from the README. Browser audio requires a user gesture, and public Pages deployment depends on GitHub Pages configuration and build success.

## Safety

Visual disk utilities, terminals, BIOS, faux login dialogs and network maps are simulations. Interactive mini-games and drawing tools run locally in the visitor's browser. The optional public GitHub activity feed performs a read-only request. Local note storage is not encrypted and should not be used for secrets. This design document is not a claim of production uptime, completed GitHub Actions checks or browser compatibility testing.
